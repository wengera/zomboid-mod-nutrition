## The standing spec contract — every `Shape:` cell below inherits all six clauses

The brief makes these mandatory on **every** spec, so they are stated once and bind each row.
A row's `Shape:` cell names only what is *particular* to it.

1. **Profile.** An existing `testing/profiles/<name>.toml`, or a new one **in
   `testing/profiles/mod-under-test.toml`'s shape**: bare keys first (`fixture`, `description`,
   `run = { hold = N }`, `verify = [...]`, optional `client = { timeout = N }`), then `[[mods]]`
   in `Mods=` order with `PZTestKit` **first**, each further mod carrying `id` + `workshop_id`
   **or** `path`, then `[sandbox]` (validated against the fixture's own
   `pzt_SandboxVars.lua`). **`[[verify]]` rows are tier-(a) gates only** — certain to pass if the
   mod loaded at all, never a measurement (`x12-pcall.toml`'s `TKX_P.version` is the model). A
   reading that is the point of the session is never a gate, and a gate on the side whose loading
   is itself the question turns that reading into a boot requirement, so it is put on the other
   side (`x12-pcall.toml`'s ungated server, inverted where noted).
2. **Driver.** `testing/experiments/x131_*.py` in **`x121_overrides.py`'s shape** (`td3_autocook.py`
   is the sibling): provenance keys `commit`, `harness_lua_commit`, `harness_lua_dirty`,
   `doctor_clean`, `acceptance_run`; **client-first paired reads** at every tag (the two sides are
   separate bus round trips ~1 s apart, so the sign of a cross-side comparison otherwise follows the
   read order — `decisions.md:158` (at the tag `research-program-v1`)); **driver-side wall brackets** on every read, with tags
   **named by what was measured, not by the sleep that was asked for**; the **re-ask-once guard**
   (`TK.writeKV` writes the ack non-atomically; a non-table where a table belongs is re-asked once
   and **both** readings kept); **per-scope modData exclusion sets**
   (`VANILLA_PLAYER_KEYS = {fitnessMod, fitnessUpTimer, strengthMod, strengthUpTimer, hotbar}`,
   `VANILLA_ITEM_KEYS = {customName, Tooltip}`, applied to their own scope and no other);
   **`field_count == N`** asserted per read against a declared expectation; console greps with a
   **compiled** regex and a limit **≥ 2 × predicted** (a result of exactly `limit` is saturation,
   and a client prints each mod's block **twice** — two Lua states); explicit
   `predictions` / `observations` / `verdicts` with the vocabulary
   `as_predicted | falsified | trivial | unmeasured`; `try/except/finally` that **always** saves the
   artifact; world changes either restored inside the `try` or named in `out["world_changes"]`.
3. **Action.** A bus call that **exists** — verified against the live registration set, not against
   prose (`README.md` (the testing docs, at the tag `research-program-v1`) § Command bus is the inventory bullet, and it trails the harness:
   the live set is **56 distinct names over 64 `TK.register` calls** (re-counted 2026-09-17; the
   eight registered **twice**, once per side, are `nutrition.get`, `nutrition.set`, `stats.get`,
   `stats.set`, `sandbox.set`, `perk.set`, `moddata.set` and `item.script`, and the 65th
   `TK.register(` hit is the **definition** at `PZTestKit_Core.lua:513`, not a call) in
   `testing/PZTestKit/PZTestKit/42/media/lua/{shared,server,client}/`) — **or** a harness addition
   under the standing rule, which every such row **names explicitly**, with its own commit, its
   README § Command bus inventory line, `python tools/luabalance.py <lua files>`
   (HEAD copies first, then the working tree) and the **next acceptance run as its smoke test**,
   landing **before** the session. 4. **A reading that DISCRIMINATES.** "Both sides agree" is not a result unless the sides were first
   made to differ, and every row below names the control that makes them differ. A reading that
   comes back trivial, unmeasured or falsified is **written as such** and never re-run for a
   prettier number.
5. **One session.** ≈ 3 min live, **≤ 2 h with the write-up**. A hole needing more is **split**, and
   § Splits says so.
6. **Raising probes** (X16, X23, X26, and any row whose mod may raise): **gate on the SERVER** —
   a `[[verify]]` client row never runs when the client hangs; set **`[client] timeout` low**
   (60 s, against the 300 s default) so a parked client costs a minute rather than five; and
   **expect `pzt run` to report FAIL**, because the run classifier counts the trace blocks. That
   FAIL is the profile working as designed, not a profile error, and the driver's `predictions`
   say so in as many words. The debug client is **stopped dead** by the first mod Lua error that
   reaches `KahluaUtil.fail` (**lua-api L5**), which is why X23 exists at all.
