# Artifacts register

Tracked, immutable copies of the **measured evidence** that the docs cite as `M` rows live under `testing/artifacts/`; this page is their register.

- One folder per run id (`<experiment>-<UTC timestamp>`), holding the result JSON that
  experiment wrote — and nothing else, unless a doc's `M` claim rests on a file that JSON does
  not contain. Then that file is committed beside it, byte-for-byte, and the Contents row names
  it: `run-20260910-133657/pzt_SandboxVars.lua` is the only one so far.
- Copied into `testing/artifacts/` byte-for-byte at slice close, from the run directory that produced them.
  Verify with `sha256sum`; never hand-edit a file under that directory. The local
  `.gitattributes` sets `* -text` so the committed blob is byte-identical to what the
  experiment wrote — without it `core.autocrlf` would rewrite the CRLF newlines and the
  hashes would not match.
- The **full** run directories — server and client logs, stdout, per-client dumps — stay
  local under `testing/runs/`, which is gitignored (`.gitignore:44`). They are large,
  machine-specific, and regenerated by re-running the experiment.

Why this exists: an `M` grade in `docs/` claims something was measured. That claim has to
be checkable from a fresh clone, so the numbers behind it are committed and the docs cite
these paths rather than a path that only exists on the machine that ran the experiment.

A committed artifact is evidence, not an oracle: a key can be *present and wrong* when the
script that wrote it had a defect. Where that is known, the run's reading guide lists the key
under **do not cite** and says what to read instead. Nothing here is ever hand-edited to
correct it.

Each run's reading guide is its own `testing/artifacts/<run>/GUIDE.md`, linked from its row below: how
to read the files, the run's skew and its *do not cite* keys. The guide is the one file in a run's
folder that is not evidence and that may be edited; a guide that says another run's block is above or
below means that run's own guide.
