# Plan 8 — Sync and Persistence Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the mod's state survive what a live server does to it — a reconnect, a respawn, a clean restart, a hard kill and a second client — and reconcile the intakes other mods' eat actions hide from the wrapped seat, each behaviour measured on a dedicated server with two driven clients.

**Architecture:** Two pure kernel files carry the new logic: `K.store` (the record's version, the inputs-only contract, a load that migrates an older record and drops every derived field so a formula change needs no migration) and `K.reconcile` (the per-minute comparison of the vanilla macro stores against the mod's own last write or observation, yielding a missed-intake delta as macros only). Two server adapters apply them on the slow clock; the bus gains a band-change mark beside the effects mark so the mirror goes out on any grade or band change, at most once a minute, and on first sight after a reconnect or a respawn. The harness gains a second provisioned client, a driver API that addresses a client by name, and two test-only commands (`event.trigger`, `lua.callm`) that settle Plan 7's key-press and wheel rows. Three live sessions grade the whole: the Nutritionist-gate race, persistence and lifecycle, and two clients.

**Tech Stack:** the mod's Lua (Kahlua subset; `lupa` 2.8 kernel tests), the harness (`pzt`: provision, run, the file bus, `make_server(reuse=True)`, `make_client` per user), the claims register and its delta tools.

**Spec:** `docs/superpowers/specs/2026-09-27-nutrition-mod-design.md` — § 4.8 (default: the mirror message's triggers and cadence; the one client request; missed-intake reconciliation; persistence as the global table keyed by username, inputs only, a version field, derived on read; respawn on `OnNewGame`, reconnect on first sight, a dead record kept until respawn; X28), § 4.1 (durable state is one global modData table cached server-side, never player modData), § 4.9's rows for the eat/drink replacers (reconciliation) and ApocalipseBR (redundant), § 4.10 tier 4 (a rejoin and a restart for persistence; paired client-first reads graded against a skew band; a two-client session once the harness supports one), § 5 row 8 (X28 measured — run `x131p-20261004-192310`, rows #1294/#2756/#2098/#2758; "second-client support in `pzt`"), § 7 items 23, 24, 37, 38. The pages: `docs/areas/mp-sync.md` (its `## Rules` are the constraints; its walls name what no route offers), `docs/platform/server-lifecycle.md` (the join, creation, death, addressing and store rules), `docs/platform/harness.md` (the driven client, the bus, the procedure), `docs/areas/testing-your-mod.md#grading` (the skew band). Plan 7's open rows this plan takes: #3241 (the Nutritionist-gate race), #3247 (the key press), #3248 (the scrolled clip) and #3246's tab branches as far as a method call reaches them; the mod bug #3240.

## Global Constraints

Everything in Plan 7's Global Constraints holds (`docs/superpowers/plans/2026-10-06-plan-7-interface.md`), and through it Plans 2–6's. Plan 8 adds:

- **The authoritative copy of every per-player value is the server's record in `NutritionRevamp.players`**, keyed on `getUsername()` (#2410), cached as the table itself, never player modData (#1042, #1151) and never transmitted (#2416): a client holds only the mirror the bus sent it.
- **The record holds inputs only, under a version field, and everything else is derived on read** (spec § 4.8): `K.store.INPUTS` is the closed list of paths the record persists; a field outside it is rebuilt by the next slow minute from the inputs and never read back from disk; a record of an older version is migrated by `K.store.load` and the migration is a kernel function with a test per version step.
- **The mirror goes out on first sight, on any grade or band change, and otherwise at most once per minute** (spec § 4.8): the bus's `PUSH_GAP_MS` gap applies to every change-triggered push; the first-sight push is unconditional; the one client request answers at once.
- **Every player-addressed server send reaches that player's own client only** (#2603): a two-client arm proves the mirror, the effects push and the trait push land on the owner and not on the other client, and that the global table is on no client.
- **Reconciliation lands macros only, never a nutrient vector**, with `lastIntake.source = "reconciled"` and a note that the vector is unknown (spec § 4.8, § 7 item 38); the vanilla update is off (`Nutrition = false`, ruling T18-1) so the stores change only through an eat, a drink, the mod's own legacy-mirror write or another mod's action; the baseline is the value the mod last wrote (LegacyMirror on) or last observed (LegacyMirror off), and only a rise above a tolerance is an intake.
- **Every live reading is a paired client-first read graded against a skew band** (#1485, #1483), and a two-client reading names which client each read came from.
- **A driver's server-log pattern excludes its own probe names** (CLAUDE.md § 5); **a client-local trait add is never a gate test's instrument** until #3241 is separated (this plan's first live arm).
- **Pytest floor 2416**; the close writes the new count into CLAUDE.md § 3.
- **Rulings this plan takes** (each a ledger line and a `Ruling:` row at the close; 2–16 are controller defaults listed for Angus's § 7 re-review):
  1. **One plan for § 5 row 8,** measure-first on the harness: Task 1 (the two-client fixture and the named-client driver API) ∥ Task 2 (the two bus commands) ∥ Task 3 (the store and reconcile kernels) → Task 4 (the server adapters and the band mark) → Task 5 (live: the gate race and the input commands' smoke test) → Task 6 (live: persistence and lifecycle) → Task 7 (live: two clients) → Task 8 (docs) → Task 9 (close).
  2. **The second client is a provisioned fixture user `bob`** in a new fixture `two` (`pzt provision --name two --clients admin bob`), a non-admin account launched WITHOUT `-debug` (the provision's own rule for a non-admin user): a release client, which is also the user-role, non-debug client Plan 6's checksum gate and X23 wanted; if character creation cannot be driven on a non-debug client, the task measures that and `bob` is re-provisioned with `-debug` under a stated ruling.
  3. **A driver addresses a client by name:** `step(name, "client:bob", cmd, args)`; the bare `client` side stays `admin`; the profile's `clients = ["admin", "bob"]` key lists the fixture users a run attaches (the default `["admin"]` keeps every existing profile unchanged).
  4. **The two bus commands** are `event.trigger <EventName> [scalar ...]` (both sides; `triggerEvent` guarded; test-only) and `lua.callm <a.b.c> <method> [scalar ...]` (both sides; calls `obj:method(args)` on the table at the dotted path; test-only), each in its own commit; they settle #3247 (a key press through `OnKeyPressed`), #3248 (the panel's `onMouseWheel`) and the tab's render and tear-off methods as far as a method call reaches them — the on-screen pixels stay unmeasured and the rows say so.
  5. **`K.store.VERSION = 2`**: the inputs list is written down (the nutrient pools `p`/`p2`/`ah`/`e24`/`dmg`/`ext`/`ax`/`axr`, the body masses and the day accumulators, the stomach buffer, the acute scalars, the fluids scalars, the flags, the identity fields `username`/`firstSeen`/`lastSeen`/`resets`/`dead`); `g`, `gl`, `x`, `band`, `energyState`, `tac`, `dmod`/`rmod`, the effects set and every mirror-only scalar are derived and dropped at load; a v1 record migrates by keeping its inputs and dropping the rest; a record with no version is v1.
  6. **Reconciliation runs on the slow minute before the legacy mirror's write**: `delta = store − baseline`; `baseline` is the legacy mirror's last written value when LegacyMirror is on, else the last observed value; a `delta.calories > RECONCILE_EPS` (5 kcal, a game choice) with the matching macro deltas lands `K.stomach.add` with the four macros only, `source = "reconciled"`, a counter and the note; a fall is ignored; the baseline is reset to the store after every landing and after every wrapped eat/drink (the intake records what it expects the store to show).
  7. **The band mark:** the Weight adapter calls `B.markBand(username)` when the body band changes; the bus treats it as the effects mark (one gap, one flush); the first-sight and `OnNewGame` sends stay unconditional.
  8. **A reconnect is a departure then a first sight**: the players' walk drops the username on departure (the transient bus state forgotten) and re-fires first sight when it returns, which sends the one first-sight mirror from the stored record; nothing else is needed and the arm measures it.
  9. **A respawn is driven, if the harness can**: the character is killed by a server write (`stats.setany <user> Health 0` or the jar's die route — the implementer reads what exists) and the respawn flow on a `-debug` client is driven through `lua.callm` on the post-death UI's respawn method (the implementer reads `ISPostDeathUI.lua`); if it cannot be driven the arm is written unmeasured, never worked around.
  10. **The restart arm reads the mod's own table**: a clean quit then `make_server(reuse=True)` must read every record input back and the next slow minute rebuild the derived fields; a hard kill after a write loses what X28 says it loses (#2098) — the arm restates #2098 for the mod's table and does not re-measure the engine.
  11. **The two-client session** runs `admin` (debug) and `bob` (release) on fixture `two` with the mod: each client's `received` mirror is its own; a forced deficiency on `bob` (the global table written on the server) reaches `bob`'s mirror and not `admin`'s; a trait push on `bob` reaches `bob`'s list and not `admin`'s copy of `bob`; `bob`'s client holds no `NutritionRevamp.players` global modData (the census must miss); a server-side calorie rise on `bob` with no eat is reconciled on the next slow minute; `bob`'s panel toggles through `event.trigger OnKeyPressed 39` on `client:bob`.
  12. **The Nutritionist-gate race (#3241) is this plan's first live arm**: on `admin`, the client's trait list is re-read every 0.5 s for 5 s after a client-local add and once more at the mirror's arrival, and a second add is sent synced (`trait.local NUTRITIONIST add sync` if the harness's command takes the flag — read it; else `trait.add.push` from the server) with the same reads; the row settles if the lost-before-arrival branch or the read-missed branch is seen, and stays open otherwise.
  13. **The band's rich/low bug (#3240)** is fixed in Task 3's kernel touch: `K.view.requirements` keys the records by the vector key the UNITS table uses (`retinol` for `vitA`) and includes a scaled record at its base requirement; a test pins vitamin A, thiamine, niacin, B6 and K as rankable.
  14. **Not this plan:** the release packaging and the five subscribe-and-read code reads (Plan 9); a client-side prediction of any mod value; a per-key intake history; the hover synthesiser (a pixel reading has no instrument); X14, X27, X17.
  15. **ApocalipseBR Nutrition Sync Fix** is not installed here; the page states the redundancy from the spec's row and no run measures it.
  16. **A run with two clients holds one session** in the repository-wide sense: both clients belong to one `pzt run`, and the one-session rule is unchanged.
