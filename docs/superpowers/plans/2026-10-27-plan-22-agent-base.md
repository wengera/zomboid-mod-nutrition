# Plan 22 — the agent base (K1): a thin Lua motor and sensor on the typed PZA/1 protocol, every policy in Python

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the agent link as candidate K1: one JSON schema (`PZA/1`) generating the Lua constants and positional encoders, the Python decoders and the LLM tool descriptions; a Lua motor that runs and sprints from `OnPlayerUpdate`; typed one-step skills; a Link with one flush a tick under a byte budget; a map from first sight with a dirty set; a narrow server `damage.watch` listener; a Python `World`, `Actions` and `Transport` seam with the fight, flee, explore and loot policies ported out of Lua; then two measurement sessions (X4 the link, X5 combat) and one survival acceptance run, each graded off an artifact.

**Architecture:** Plan 21's Python layer (`testing/agent/link.py`, `world.py`, `policy.py`, `reasons.py`, `summary.py`, `grades.py`, `grade_c.py`) stays in place, frozen with the drivers that import it; the new base is the package `testing/agent/base/` (`pza1.py` generated, `transport/`, `actions.py`, `world.py`, `planner/`, `gates.py`). The PZAgent client mod is rewritten in place: `PZAgent_Core.lua` (`PZA.call`, the keyed JSON encoder, a JSON decoder for `cmd.txt`), the generated `PZAgent_Schema.lua`, `PZAgent_Link.lua` (one flush, the budget, the backlog), `PZAgent_Motor.lua` (the `OnPlayerUpdate` gait), `PZAgent_Skills.lua` (the typed one-step actions), `PZAgent_Sense.lua` (the frame and events), `PZAgent_Map.lua` (the scan job and the dirty set), `PZAgent_Main.lua` (the tick order). The server gains `damage.watch` and `zombie.get` on the PZTestKit bus. Every live session is a new frozen driver on `_dlib`'s boot seams, graded by a versioned gate.

**Tech Stack:** Kahlua (Lua 5.1 dialect) under lupa 2.8's Lua 5.1 host for the offline tests; Python 3 (`pytest`, stdlib `json`, `dataclasses`); the harness `testing/pzt` (doctor, provision, run); RCON through `xlib`; detached `Start-Process` launches polled through the persisted artifact.

**Spec:** `docs/superpowers/specs/2026-10-27-plan-22-agent-base-design.md` (§ 2 the binding principles; § 4 the protocol; § 5 the actions; § 7–§ 9 the probe's settled mechanisms; § 10 the gates; § 11 out of scope). The probe's readings are `testing/artifacts/p22_probe-20261027-032502/GUIDE.md` and rows #4197–#4202.

- Spec § 2, binding on every task: **one schema, two hosts** (`PZA/1` is `testing/agent/base/schema/pza1.json`, checked against both sides by `python tools/pza_schema.py --check`; no field, kind or enum exists that the gate does not know); **observe, never echo** (a sensor reads what the engine did, never the flag the actor wrote); **skills, not machines, in Lua** (one bounded engine action with a typed result; a goal with two steps is Python's); **index-first, every member** (`PZA.call` or `X ~= nil and X.m ~= nil`; a caught raise still parks the `-debug` client, #0957); **bytes and ticks are budgets** (one flush a tick, a byte budget, overflow an event, the worst tick graded); **frozen drivers, versioned gates, replays**; **no server component on the control path** (server reads grade; `damage.watch` is the one listener).

- Spec § 10 gates, each versioned and graded off an artifact: X4 tick mean < 1 ms at 60 Hz over 1800 ticks; worst `OnTick` ≤ 3 ms and 0 ticks ≥ 5 ms over 10 minutes on the 1 ms clock (ruling P22-4); 0 gaps; 0 Lua errors; 0 parks; ack → first move p90 < 500 ms; the kept map ≥ 99 % of walls, doors, windows and containers against one full scan at the end.
