# Plan 7 — Interface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the player the mod's state through four client surfaces — a collapsible panel, a food-tooltip band, a character-info tab and optional moodles — gated on the Nutritionist trait or a server option, with every string translated and nothing server-side reading a display name.

**Architecture:** One pure kernel file (`NR_Kernel_View.lua`, `K.view`) turns the client's stored mirror into a row model at one of three visibility levels, and every surface draws that model; the surfaces are five client files (`NR_Client_ModOptions`, `_View`, `_Panel`, `_Tooltip`, `_Tab`, `_Moodles`) that derive vanilla widgets or wrap one vanilla method each behind a sentinel global, read the mirror only when its arrival counter moves, and call every engine and framework member through the index-first guard inside a protected call. The tooltip's vector is the intake's own source chain, factored into a shared kernel function so the band shows what the eat would land. The server side gains only the `VisibilityMode` option and two mirror key families (`nut_<key>_p`, `nut_<key>_x`).

**Tech Stack:** the mod's Lua (Kahlua subset; `lupa` 2.8 kernel tests), the vanilla `ISUI` toolkit (`ISCollapsableWindow`, `ISLayoutManager`, `ISPanelJoypad`, `ISToolTipInv`, `ISCharacterInfoWindow`), `PZAPI.ModOptions`, `MoodleFramework` (optional, detected), the harness (`pzt`, PZTestKit, TKX probes, profiles), the claims register and its delta tools, Python 3.13 stdlib for the icon generator.

**Spec:** `docs/superpowers/specs/2026-09-27-nutrition-mod-design.md` — § 4.7 (default), § 4.8 (the mirror and the one client request), § 4.9 (the layout: `common/`, no vanilla relative path, MoodleFramework detected never required; the tooltip-mods, moodle-skins and food-content rows), § 5 row 7 (gates X29, X5; "a click or key synthesiser if a panel state must be read by the bus"), § 7 items 20, 21, 44, § 8 (X29, X5). The platform briefing is `docs/superpowers/research/platform-client-ui.md` (the worked shapes 1–4, UNTESTED: every risk its shape names is a reading of this plan's acceptance boot) and `docs/superpowers/research/moodleframework-desk-read.md`; the pages are `docs/platform/client-ui.md` and `docs/areas/ui-and-moodles.md` (their `## Rules` are this plan's constraints, quoted below by row).

## Global Constraints

Everything in Plan 6's Global Constraints holds (`docs/superpowers/plans/2026-10-06-plan-6-item-pass.md`), and through it Plans 2–5's. Plan 7 adds:

- **Everything on these surfaces runs on a client** (#2522): every new file is under `common/media/lua/client/` except the kernel (`shared/`) and the option (`42.20.4/media/sandbox-options.txt` + the server reader); a dedicated server builds no panel, draws no tooltip and loads no texture, and no server file names `getText`, a display name or a texture (#1026, #2489).
- **No file at a vanilla relative path** (spec § 4.9; `CleanUI` ships 43 of them, #2497): every file is `NR_`-prefixed and every wrap is a method wrap installed from the mod's own file.
- **Every wrap is sentinel-guarded in a global of its own, keeps the original, and re-wraps only when the class table was re-created** (#1067, #0943, lessons `:33-34`); the tooltip wrap repeats the context-menu test and frames its own band below Java's box (#2516, #2517); the tab wrap installs at file scope and never writes the tab's name into `layout.current` (#2521); the keybind row and the options page exist at file scope and `PZAPI.ModOptions:load()` is called by the mod once, after the page exists, inside a protected call (#2519, #2520).
- **The mirror is read at the push cadence, never the frame cadence** (#2692): a surface compares `NR.client.received` per frame and rebuilds its row model only when it moved; nothing walks the mirror in `render`.
- **Every engine, toolkit and framework member is reached by the index-first guard inside a protected call** (#0935, #1072, #2546): `MoodleFramework` contains no `pcall` of its own; the harness client runs `-debug` and parks on an unguarded raise (#0954).
- **No moodle type is registered through the vanilla registry** (#1140); the mod's moodles are framework widgets or its own `ISUIElement` column (#2555).
- **Trait tests compare the registry object, never a name** (#0550, #1162): `CharacterTrait.NUTRITIONIST` / `NUTRITIONIST2` through `hasTrait` (#0551), behind a nil check on the enum.
- **Translations are B42 JSON under the mod's prefix** (`UI_NR_*`, `IGUI_NR_*`, `Moodles_NR_*`; #1025, #2552) and no vanilla key is redefined by the mod whatever X5 reads (ruling 12).
- **Every number the surfaces show is the mirror's or the shared table's, never a client getter the wire transforms** (#1084, #1147): a cooked food's thirst is never shown; the tooltip's macros are the script's.
- **Pytest floor 2100**; the close writes the new count into CLAUDE.md § 3.
