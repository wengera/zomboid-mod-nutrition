# `x26-regrade-20261010` reading guide

**`x26-regrade-20261010/summary.json`**, **`x261.json`**, **`x262.json`**, **`x263.json`**, **`x264.json`**, **`x265.json`** and **`x266.json`** — a derived artifact: a tool re-run, not a live run. Produced by `testing/experiments/x26_regrade.py`, committed at `6575cc5` with the tool change it exercises (`tools/replay_live.py` at `6575cc5`: the required `sleep_allowed` input, the option the mod reads in `NUT.readSleepOptions`, `NR_Server_Nutrients.lua:127-143`, and the opt-in auto-drink detector), over the six committed runs `x261-20261010-120313` to `x266-20261010-124534`; nothing is booted. Its inputs are each run's committed `events.json` (the logged events only), `start.json`, `start-stats.json`, `player.json` and ring pages, with `sleep_allowed` false (the live server's SleepAllowed and SleepNeeded) and `detect_autodrink` on (`flags`); of the run's own replay it reads only the diff, copied as `run_time_tool_diff`, and the driver's verdicts, copied as `driver_verdicts`. It replaces the frozen run-time grader `testing/experiments/x26_meals_grade.py`, which no longer runs against the tool at `6575cc5`. `python testing/experiments/x26_regrade.py` reproduces the folder byte for byte except each run file's top-level `seconds`, the wall time of the tool run (`x261.json` 6462 bytes, sha256 `7276fb23…300e37bc`; `x262.json` 7238, `bb2d4941…1fa092c7`; `x263.json` 10669, `5ab4dff7…757724dc`; `x264.json` 6230, `c67956bb…d8426d1c`; `x265.json` 3749, `7b3f4172…8c78a59d`; `x266.json` 7145, `6d63f6d3…45b2b242`; `summary.json` 6462, `f448cde8…7b6b677d`).

How to read it. Every reading here is the replay's own, `tools/replay_live.py` at `6575cc5` over the committed inputs; the live values beside them are copied off the committed rings. Each run file holds `regrade` (the replay with the sleep option mirrored and the auto-drink detector on: `diff`, `diff_extra`, `findings`, `injected`), `sleep_only` (the same without the detector), `requests` (each landed eat's request minute, `live` and `replay`, with `tol` max(3, 2 % of the replay's minute) and `ok`; `readings.requests` repeats them), `readings` (the row's arms and figures, cited from the run's guide above), `injected_events`, `run_time_tool_diff` (the run's own `replay.json` diff, copied) and `driver_verdicts` (the run's verdicts, copied); `summary.json` holds one line a run.
- **The verdict at HEAD**: every run reads `regrade.diff.ok` true with no field over tolerance: HUNGER max 3.13e-4 (x261), 2.84e-4 (x262), 1.59e-4 (x263), 1.63e-4 (x264), 8.36e-5 (x265) and 4.30e-4 (x266); `body.energyState` at most 1.26e-3; `satiety.L` 0. Every labelled request is `ok`.
- **The one injected auto-drink**: `x263.json` `injected_events` holds one drink, 0.2002 L of Water at ring row 179, the engine's auto-drink of `x263-20261010-122318` (F-T4-2); no other run has one. Without it (`x263.json` `sleep_only`) the HUNGER diff reads 0.0071, as the run-time tool did.
- **The tool gap** (`run_time_tool_diff`, `summary.json` `runs.<run>.run_time_tool_ok`): the run-time tool read falsified on x261, x262 and x266 (HUNGER max 0.0470, 0.0465, 0.0702 over 415, 565 and 1519 rows, all from the 24 h window close, F-T4-1) and on x263 (0.0071 over 25 rows, F-T4-2); x264 and x265 read ok at run time. These are readings of the tool before `6575cc5`, not of the mod.
- **The x264 means** (`x264.json` `readings.means`): a window is cut at the next eat's landing (`minutes_used`, `truncated_at_next_landing`, `readings.means.note`); MSOUP's is 150.99 min.
- **The x262 censored arm**: `x262.json` `readings.snack_arms.C` is censored (`censored` true): its P and F arms' dinner falls past the next live eat, and their `dinner_from_lunch` 1004.14 is the ring's end, not a request.
